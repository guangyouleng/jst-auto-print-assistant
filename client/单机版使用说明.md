# 单台电脑打单：无需部署协调服务器

单机模式在本机执行订单筛选、精确回读、任务预留、完成核验和永久跳过。查询直接访问聚水潭开放 API，取号、改快递和打印继续由已登录的本机 Chrome / Edge 执行。程序不执行预发货或直接发货。

不需要运行 `server/`、systemd、反向代理或 ERP bridge 服务，也不需要配置原后台地址和 Bearer token。`server/` 保留为旧部署和历史回归资料；单机运行及客户端打包无需携带该目录。远程模式仍兼容旧配置。

## 1. 选择单机模式

`client/jst_operator_config.json` 使用：

```json
{
  "backend_mode": "local",
  "debug_port": 9222,
  "loop_seconds": 5
}
```

可以从 `jst_operator_config.example.json` 复制。本机工作副本已切换到单机模式。旧安装包不会自动更新，应使用修改后的源码或重新打包。

## 2. 配置聚水潭只读查询凭据

本机仍需已有聚水潭开放 API 的三项凭据：`app_key`、`appsecret`、`access_token`。源码压缩包不包含这些值。

### Windows：界面输入与 DPAPI 加密

首次启动若没有加密配置，会自动弹出“聚水潭凭据设置”。填写三项凭据，点击“验证并保存”。程序先执行一页、一条的出库单只读查询，成功后使用 Windows 当前用户范围的 DPAPI 加密保存至 `%USERPROFILE%\.jst-auto-print\jst_openapi_config.dpapi`。未保存前不能开始自动打单；保存成功后仍需手动开始。

同一台电脑、同一 Windows 用户下，后续启动自动读取。配置缺失、损坏或因换电脑/用户而无法解密时，会再次弹窗。不要把加密凭据或真实凭据放入安装包；换电脑通常需重新输入（Windows 域漫游配置可能允许跨电脑解密）。

随时可点击“聚水潭凭据设置”更新。必须先停止打单并等待引擎退出，暂停状态不能修改。密钥和 Token 默认隐藏显示。验证或加密保存失败时保留原配置；网络故障只提示重试，不判断为凭据过期。聚水潭业务错误码 `503/504` 会要求更新，运行中的任务先按既有安全边界停止，再显示设置窗口；原任务记录保留，重新启动后仍需回读核验。

旧 `jst_openapi_config.json` 或 `JST_APP_KEY/JST_APP_SECRET/JST_ACCESS_TOKEN` 环境变量仅用于首次设置窗口预填，Windows 业务查询不再直接使用它们。验证并保存成功后删除本机旧明文 JSON；删除失败会提示手动清理。程序不会修改系统环境变量，旧环境变量请自行清理。已有加密配置不会被环境变量覆盖。

DPAPI 使用微软的 [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata) 系统 API，不增加 Python 加密库依赖，不使用固定内置解密密钥，也不自动刷新聚水潭 Token。访问令牌过期需自行获取新 Token 后在界面更新。DPAPI 保护磁盘上的凭据，不能防止同一用户下的恶意程序读取运行时凭据。

### macOS：保留现有配置方式

DPAPI 仅支持 Windows。macOS 暂时从 `~/.jst-auto-print/jst_openapi_config.json` 读取明文 JSON，内容参考 `client/jst_openapi_config.example.json`；也支持上述三个环境变量，环境变量优先。请限制文件权限，不要提交到 Git 或发送到聊天中。macOS 的“聚水潭凭据设置”按钮显示说明，不会降级保存所谓的加密文件。

查询模块只允许店铺、出库单和订单操作历史三个查询方法。沿用服务器源码中的网关和签名协议，不包含刷新 token、业务写入或数据库日志功能。访问令牌失效后 Windows 在设置窗口更新，macOS 更新本机配置。

如查询返回错误码 `506`，检查原应用是否限制了服务器出口 IP；本机出口也需获得相应查询权限。错误码 `503/504` 表示凭据失效，需要更新凭据；程序不会忽略错误继续打单。

## 3. 历史任务与永久跳过

原本机 `events.sqlite3` 和事件记录继续使用。首次迁移会：

- 将本机已有的永久排除和终态记录导入本地预留数据库，不受请求中 200 条排除限制。
- 保留旧活动任务的订单对与令牌；`PREPARING/RUNNING` 的状态、步骤仍由原事件数据库保存，通过现有只读恢复流程核对，不直接重放业务动作。
- 身份或令牌不完整时停止迁移，要求先核对旧任务。

新的永久跳过和完成记录保存在 `~/.jst-auto-print/local-reservations.sqlite3`，重启后继续生效。请与 `events.sqlite3` 一并备份，并在程序停止时进行备份。

只存在于原服务器、未同步到这台电脑的永久跳过记录不会自动迁移；切换前应确认本机记录完整，或先另行导出迁移这些记录。不要在旧服务和单机版上同时处理同一批订单。

## 4. 启动与验证

在 `client/` 中执行：

```bash
python3 jst_auto_print_app.py --self-test --self-test-output /tmp/jst-local-self-test.json
python3 -m unittest discover -s tests -p 'test_*.py'
python3 jst_auto_print_app.py
```

Windows 使用原有 Python 3.10 x64 启动和打包入口。构建配置校验已支持 `backend_mode=local`；新的本地模块通过 Python 导入进入打包分析，无需安装 HTTPX、SQLAlchemy、python-dotenv 或完整 ERP bridge。

启动时选择面单类型、确认打印纸并登录专用浏览器。启动检查使用一页、一条的出库单只读查询，不额外要求店铺查询权限。`--live-readonly-probe` 可验证只读查询及浏览器链路；它不取号、不改快递、不打印。

`--no-print` 仍可能改快递和取号，仅适用于已批准的验收订单。实体打印需要现场验证。

单机模式保留精确订单对、完整 SKU 明细、完整操作历史和自动完成证据校验；仅有打印标记不能证明打印完成。遇到查询不完整、分拆出库身份、含糊动作或未知状态，继续停止自动处理。
