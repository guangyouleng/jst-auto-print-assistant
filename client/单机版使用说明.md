# 单台电脑打单：无需部署协调服务器

单机模式在本机执行订单筛选、精确回读、任务预留、完成核验和永久跳过。查询直接访问聚水潭开放 API，取号、改快递和打印继续由已登录的本机 Chrome / Edge 执行。程序不执行预发货或直接发货。

不需要运行 `server/`、systemd、反向代理或 ERP bridge 服务，也不需要配置原后台地址和 Bearer token。`server/` 保留为旧部署和历史回归资料；单机运行及客户端打包无需携带该目录。远程模式仍兼容旧配置。

## 1. 选择单机模式

`client/jst_operator_config.json` 使用：

```json
{
  "backend_mode": "local",
  "debug_port": 9222,
  "loop_seconds": 5
}
```

可以从 `jst_operator_config.example.json` 复制。本机工作副本已切换到单机模式。旧安装包不会自动更新，应使用修改后的源码或重新打包。

## 2. 配置聚水潭只读查询凭据

本机仍需已有聚水潭开放 API 的三项凭据：`app_key`、`appsecret`、`access_token`。源码压缩包不包含这些值。

在当前打单电脑创建凭据文件：

- Windows：`%USERPROFILE%\.jst-auto-print\jst_openapi_config.json`
- macOS：`~/.jst-auto-print/jst_openapi_config.json`

内容参考 `client/jst_openapi_config.example.json`：

```json
{
  "app_key": "填写已有应用编号",
  "appsecret": "填写已有应用密钥",
  "access_token": "填写已有访问令牌"
}
```

Windows PowerShell 本机准备命令（在仓库根目录执行）：

```powershell
$Target = Join-Path $env:USERPROFILE '.jst-auto-print'
New-Item -ItemType Directory -Force -Path $Target | Out-Null
$Config = Join-Path $Target 'jst_openapi_config.json'
if (!(Test-Path $Config)) {
    Copy-Item client/jst_openapi_config.example.json $Config
}
notepad $Config
```

macOS 本机准备命令（在仓库根目录执行）：

```bash
mkdir -p ~/.jst-auto-print
cp -n client/jst_openapi_config.example.json ~/.jst-auto-print/jst_openapi_config.json
chmod 600 ~/.jst-auto-print/jst_openapi_config.json
```

也支持环境变量 `JST_APP_KEY`、`JST_APP_SECRET`、`JST_ACCESS_TOKEN`，环境变量优先于本机文件。凭据以明文 JSON 保存，不加密，也不提供界面输入、更新按钮或自动配置弹窗。不要把真实凭据放入安装包或提交到 Git。

访问令牌失效后，先停止程序，手动修改本机 JSON 或环境变量，再重新启动。程序没有自动刷新 Token 功能。更换电脑时可自行配置或复制上述 JSON。之前加密版本生成的 `jst_openapi_config.dpapi` 不再读取，需另行提供普通 JSON 或环境变量；程序不删除旧文件。

查询模块只允许店铺、出库单和订单操作历史三个查询方法。沿用服务器源码中的网关和签名协议，不包含刷新 token、业务写入或数据库日志功能。访问令牌失效后需手动更新本机配置。

如查询返回错误码 `506`，检查原应用是否限制了服务器出口 IP；本机出口也需获得相应查询权限。错误码 `503/504` 表示凭据失效，需要更新凭据；程序不会忽略错误继续打单。

## 3. 历史任务与永久跳过

原本机 `events.sqlite3` 和事件记录继续使用。首次迁移会：

- 将本机已有的永久排除和终态记录导入本地预留数据库，不受请求中 200 条排除限制。
- 保留旧活动任务的订单对与令牌；`PREPARING/RUNNING` 的状态、步骤仍由原事件数据库保存，通过现有只读恢复流程核对，不直接重放业务动作。
- 身份或令牌不完整时停止迁移，要求先核对旧任务。

新的永久跳过和完成记录保存在 `~/.jst-auto-print/local-reservations.sqlite3`，重启后继续生效。请与 `events.sqlite3` 一并备份，并在程序停止时进行备份。

只存在于原服务器、未同步到这台电脑的永久跳过记录不会自动迁移；切换前应确认本机记录完整，或先另行导出迁移这些记录。不要在旧服务和单机版上同时处理同一批订单。

## 4. 启动与验证

在 `client/` 中执行：

```bash
python3 jst_auto_print_app.py --self-test --self-test-output /tmp/jst-local-self-test.json
python3 -m unittest discover -s tests -p 'test_*.py'
python3 jst_auto_print_app.py
```

Windows 使用原有 Python 3.10 x64 启动和打包入口。构建配置校验已支持 `backend_mode=local`；新的本地模块通过 Python 导入进入打包分析，无需安装 HTTPX、SQLAlchemy、python-dotenv 或完整 ERP bridge。

启动时选择面单类型、确认打印纸并登录专用浏览器。启动检查使用一页、一条的出库单只读查询，不额外要求店铺查询权限。`--live-readonly-probe` 可验证只读查询及浏览器链路；它不取号、不改快递、不打印。

`--no-print` 仍可能改快递和取号，仅适用于已批准的验收订单。实体打印需要现场验证。

单机模式保留精确订单对、完整 SKU 明细、完整操作历史和自动完成证据校验；仅有打印标记不能证明打印完成。遇到查询不完整、分拆出库身份、含糊动作或未知状态，继续停止自动处理。

## 5. 服务端迁移范围与差异

迁移范围为单台电脑打单所需的查询、订单规划和任务协调。客户端使用的八项协调接口（ping、plan、inspect、inspect-batch、force-skip、renew、release、complete）已有本机实现。客户端原有订单筛选、货号/SKU 排序、隐私面单、外部订单跳过、改快递、取号、批量打印、异常恢复、永久跳过和导出流程继续保留。单机版不提供跨电脑共享任务协调，也不包含完整 ERP bridge。

### 未自动迁移的服务器历史数据

只导入当前电脑 `events.sqlite3` 中已有的永久排除、终态和活动任务记录。原服务器独有的永久排除、任务完成记录、活动预留和服务器日志不会自动下载。新电脑或虚拟机也不会自动获得旧电脑的本机记录。

聚水潭中的当前订单状态和操作历史仍会查询，但它们不能替代软件自身的永久跳过决定。仅在原服务器排除过的订单可能再次进入候选范围；切换前应单独核对、导出并迁移相关记录。迁移服务器记录的工具尚未实现。

### 候选订单池的内存缓存与后台刷新

原服务器通过短期内存快照、后台刷新和共享刷新请求减少重复扫描。单机版每次规划直接执行查询，没有移植这套机制。用于保留候选订单的磁盘缓存仍然存在。

因此重复规划可能增加 API 请求量和等待时间，实际速度受本机网络及聚水潭接口响应影响。

### 完成证据的短期缓存

原服务器可复用近期验证过的精确回读证据。单机版在自动完成任务时重新回读，不复用该内存证据缓存，完成证据的校验规则继续保留。

这可能增加查询次数。打印后若网络中断，软件可能暂时无法确认完成，需保留任务并在恢复后核验，不能直接重打。

### 服务端参数的配置入口

原服务端支持环境变量调参；本机协调入口目前使用以下固定值，不自动继承原服务器的配置：

| 参数 | 单机版当前值 |
| --- | --- |
| 订单查询回溯范围 | 168 小时 |
| 操作历史查询范围 | 7 天 |
| 候选池上限 | 5000 |
| 任务预留有效期 | 300 秒 |
| 规划查询时间预算 | 105 秒 |
| 精确回读时间预算 | 通常 35 秒 |

原服务器若曾调整查询范围、候选上限或超时等参数，切换后的行为可能不同。以上时间为内部预算；不代表所有任务都能在该时间内完成。

### Token 刷新与状态数据库

提供的 ERP bridge 源码包含 `refresh_token()` 方法及数据库中的 Token 状态记录，这部分没有移植。客户端只读取 `app_key`、`appsecret` 和 `access_token`。凭据失效后需要停止程序，手动取得有效 Token、更新 JSON 或环境变量，再重新启动。

未确认原服务器是否部署了定时刷新任务；不能据此认定原部署必然会自动续期。

### 完整接口调用审计

原 ERP bridge 可将接口名称、请求参数、响应状态、耗时和错误写入数据库。单机版保留软件自身的任务、操作和异常记录，没有建立这套完整接口调用日志数据库。

本机异常导出继续可用，但不能用它查询原服务器的完整 API 调用审计记录。

### ERP bridge 的其他业务接口

本机查询模块只移植店铺、出库单和订单操作历史的只读查询。商品、分类、库存、采购、供应商、退款和售后等接口未迁移；这些不是本打单客户端的主要操作功能。单机客户端不能替代整套 ERP bridge。

### 服务端运维、隔离与诊断

单机模式不运行 HTTP 服务、Bearer 鉴权或 systemd，也没有移植服务端规划子进程的并发限制和强制超时终止。查询在客户端进程内运行，仍有网络请求超时和时间预算，但进程隔离方式与原部署不同。

现有“后台网络诊断”脚本主要面向旧 HTTP 后端，不能作为单机版的完整诊断。聚水潭凭据、任务数据库和日志需在本机维护、备份。

### 验证状态

恢复文件/环境变量配置后的回归共 383 项，381 项通过；本机端口鉴权测试因沙箱禁止监听而跳过，PowerShell 配置执行测试因当前环境缺少 PowerShell 而跳过。Windows 实际打包/安装、真实聚水潭接口和实体打印仍需现场验收。回归测试不等同于这些现场链路已经通过。
