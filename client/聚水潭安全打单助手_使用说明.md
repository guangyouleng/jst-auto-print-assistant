# 聚水潭安全打单助手 V0.5.25 使用说明

本版合入此前专用浏览器与 SKU 恢复修复，并修复 Confirmed 卡单、浏览器事件导致等待不结束、打印准备失败误记为已提交，以及恢复页面失败残留新页的问题。本次完成源码测试，Windows/Mac 成品及实体打印尚未验收。

## 单机版聚水潭凭据设置（Windows）

使用 `backend_mode=local` 时，无需部署协调服务器或填写原后台 token。首次启动没有凭据或原配置无法解密，会弹出“聚水潭凭据设置”：填写 `app_key`、`appsecret`、`access_token`，点击“验证并保存”。密钥与 Token 隐藏显示；只读查询验证成功后使用 Windows DPAPI 加密保存。

以后同一 Windows 用户正常启动无需再次输入。需要换 Token 时点击主界面的“聚水潭凭据设置”，先停止打单并等待安全停止。凭据失效会停止任务并提示更新，网络故障只提示重试；保存成功不会自动恢复打单。换电脑通常需重新填写，不能把真实凭据写入源码或安装包。没有自动刷新 Token 功能。

加密配置位于 `%USERPROFILE%\.jst-auto-print\jst_openapi_config.dpapi`。旧明文 JSON 可在首次窗口预填，保存成功后删除；清理失败会提示。macOS 暂时保留原本机 JSON/环境变量方式，不支持 DPAPI 设置窗口。

## 浏览器与登录

程序启动专用 Chrome/Edge，使用用户目录 `.jst-auto-print/browser-profiles` 内的持久化资料。首次使用需要在专用浏览器登录聚水潭一次，以后保留登录。不要求每次打开远程调试设置页。日常浏览器里的登录与这个专用资料相互独立。

生产主流程使用单条原生 CDP 连接及页面上下文 fetch，不依赖 Playwright DOM 点击。停止再开始复用健康连接；退出助手才关闭连接。程序不调用预发货、直接发货或线上发货接口。

## 启动前检查

1. 运行 `Win10_离线自检.bat`，确认 EXE、SHA256 清单、`tkinter` 和 `native_cdp` 通过。
2. 启动聚水潭本地打印组件，确认打印机联机并装好正确面单纸。
3. 点击“进入聚水潭”或“开始”启动并连接专用浏览器。默认调试端口为 `9222`，同时支持专用资料发布的实际端口。
4. 聚水潭必须已登录，且当前仓库必须是“山东汇馨仓库”。程序不会自动填写账号密码。
5. 人工选择本轮面单类型：申通普通、中通普通或中通隐私。确认实体纸张一致后再开始。

## 正常操作

1. 打开客户端，选择浏览器和本轮面单类型。
2. 点击“进入聚水潭”。程序启动或复用专用浏览器及其持久化登录。
3. 首次在专用浏览器登录聚水潭，确认只有一个打单拣货页。
4. 点击“开始”。程序每 5 秒读取后台候选，每批最多 10 单。
5. 程序会在浏览器内通过 `LoadDataToJSON` 精确查询 `o_id + io_id`，不会操作页面表格。
6. 写入前再回读后台状态和租约；通过后只提交一次取号、改快递或打印 API。
7. 操作后按每笔的 `o_id + io_id` 批量回读结果，先完成的订单先结算，不会把后一单错误归到批次第一单。
8. 打完一种面单类型后点击“停止”，人工换纸，再选择下一类型。运行中不能切换面单类型。

## 页面卡死时程序会怎么做

1. 保留当前 CDP 长连接，先做有界只读重试。
2. 明确收到页面版本过期 `ErrorCode:120009` 时，对当前打单页强制刷新并忽略 HTTP 缓存；只读请求才可自动重试，写请求不会重放。
3. 同页恢复仍失败时，在原浏览器的同一登录上下文里新建打单页。只有新页的路由、iframe 和接口上下文都完整就绪后，才关闭旧页。
4. 仍无法唯一证明页面或订单时安全暂停，绝不猜页签、不跨浏览器、不自动重登录。

## 暂停、继续与停止

- “暂停”：阻止新的最终提交，已跨过 `RUNNING` 的任务仍保留只读恢复证据。
- “继续”：先重新回读后台和浏览器接口状态，不会直接重放上一次写动作。
- “停止”：结束当前 worker，保留健康 CDP 连接及登录状态；退出整个助手时才关闭连接。

## “试运行不打印”的含义

`Win10_21H1_试运行不打印.bat` 只禁止实体打印，不是全只读模式。点击“开始”后仍可能真实：

- 重设快递公司；
- 申请电子面单号。

试运行每轮最多只处理 1 单。首次现场验收必须使用一笔事先批准的测试单，先核对改快递和运单结果，再开启真实打印验收。

## 不会自动继续的情况

下列情况会失败关闭或转入人工核对：

- 当前登录态失效；
- 存在多个真实打单拣货页，无法唯一选择；
- 订单复合身份缺失、重复、错仓库或返回额外订单；
- 已预发货、已打印、需人工保价或计划路由已变；
- 接口要求额外客户端脚本、导航或人工确认；
- 写入或打印回执不完整，无法证明每笔结果。

这些情况下不能通过反复点击“继续”绕过。不要删除 `%USERPROFILE%\.jst-auto-print`；出现问题时保留该目录的日志、报错文本和现场截图。

## SKU 出库 Excel

选择打印完成日期后导出，文件包含“SKU汇总”和“出库明细”。汇总同时按 SKU 编码和名称精确区分，编码不同或名称不同都会分行；完全相同的编码和名称合并数量，订单数去重统计。编码保留前导零，区分大小写，名称中的 `*`、`?`、`~` 按实际文字处理。

汇总数量和明细行数通过公式引用“出库明细”，重新计算后应与导出数量一致。已导出的旧文件不会自动修复，需使用更新后的程序按原日期重新导出。源码修改不会自动更新已安装的 EXE。

## Confirmed 与待人工核对

尚未提交动作的 Confirmed 订单释放租约并继续下一单。已经进入 RUNNING 的 Confirmed 订单按 UNCERTAIN_ACTION 收尾，永久退出自动队列，由人工核对。它不会被当成打印成功，不新增 SKU 统计，也不会重打。其他未知状态或证据不完整的情况仍会暂停。

升级保留 `.jst-auto-print` 数据库，不要靠删除历史任务绕过异常。
